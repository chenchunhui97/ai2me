# 学习进度与验收协议

## 事实来源

- `learning/profile.json`：用户自述背景、时间预算及尚待确认的信息。
- `learning/curriculum.json`：稳定任务 ID、依赖、相对日期、验收条件和成果位置。
- `learning/events.jsonl`：只追加的真实学习事件，按文件顺序重放。
- `learning/TIMELINE.md` / `PROGRESS.md`：生成视图，不能作为额外的独立事实来源。
- `learning/sessions/`：用户回答、运行输出、错因与辅助程度。引用代码文件时，也在 session 中保留验收命令和当时结果，Git 提交保留版本。

初始状态为未开始；背景自述不能代替实际测量。建仓和生成计划本身不计入学习完成量。

## 状态与能力

`not_started → learning → passed`；另外支持 `blocked`（需解除条件）、`needs_work`（复习失败）。通过后再次 `start` 表示重新学习；`note` 不改变状态。依赖要求当前状态为 `passed`。

| 事件 | 含义 |
|---|---|
| `start` | 真正开始任务 |
| `note` | 阅读、讲解、收集资料，不能证明独立能力 |
| `attempt` | 实际尝试，尚未通过全部验收 |
| `pass` | 独立完成全部任务验收，有证据文件 |
| `block` | 记录阻塞原因 |
| `review-pass` | 在到期复习中独立完成变式，需证据 |
| `review-fail` | 复习失败，转为待巩固；再次独立通过后恢复 |
| `correction` | 说明误记原因，以 `--state` 明确更正状态，保留原事件 |

通过和复习通过必须加 `--independent`。脚本只能防止缺文件、缺字段或依赖未通过；不能自动判断代码正确、实验可信或用户是否独立作答。一次验收通过不等于熟练，也不证明满足 JD 的多年经验要求。

每个任务的证据按需要覆盖：

1. 原理：用自己的话解释机制和适用边界。
2. 推导：公式、形状、单位、假设明确。
3. 实现：独立编码，说明参考和辅助情况。
4. 验证：与可信参考对齐，记录命令、误差、边界用例。
5. 性能：只有实测并保存配置与结果，才能声称有优化收益。

## 复习和排期

首次通过后按 1、3、7、14、30 天间隔安排复习，每次成功后从当次复习日期计算下一间隔；超过最后一档保持 30 天。复习失败转为待巩固，1 天后复习，成功后重新进入间隔序列。到期表示“应复习”，不会自动清空已有通过记录。

推荐顺序：到期复习 → 可继续的进行中／待巩固任务 → 按课程顺序选择依赖已通过的未开始任务。阻塞任务保留并列出原因，不自动跳过依赖。未到计划日期的任务可以提前做，日期是建议，不是解锁条件。

开始日期为 2026-11-07、时区为 Asia/Shanghai、每周 10～15 小时是假设。通过 `reschedule --start YYYY-MM-DD` 调整整个时间线，仅改变计划，不更改实际学习时间。调整各任务用时可编辑课程中的相对日数并重新生成。不要因日期经过而标记完成。

## 持久化

CLI 用独占文件锁保护读改写，用同目录临时文件与原子替换保存完整事件日志；新增事件后生成视图。异常退出导致视图未更新时运行 `render` 重建。损坏的 JSONL 或未知任务应明确报错，不能静默丢弃。记录使用上海时区，提交前运行 `check`。学习成果默认进入本地 Git，远端发布是独立操作。
